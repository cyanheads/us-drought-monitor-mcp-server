# us-drought-monitor-mcp-server — Design

## MCP Surface

| Tool | Description | Key inputs |
|:--|:--|:--|
| `drought_get_current_severity` | Get the latest published drought snapshot or a historical week's severity, population and DSCI changes. | Geography, optional date |
| `drought_get_timeseries` | Get weekly drought statistics and DSCI for one or more areas over a date range. | Geographies, dates, metric, statisticsType |
| `drought_compare_areas` | Compare states or counties by drought severity or change between two weeks. | Scope, date, optional baselineDate, metric, limit |
| `drought_get_weeks_in_drought` | Find county drought streaks or qualifying week counts. Any area at the category qualifies; results do not establish program eligibility. | Dates, category, minWeeks, mode, states or county |
| `drought_list_reference` | Look up drought definitions, metric support and geography identifiers. | Topic, nameContains, geography filters, cursor |
| `drought_dataframe_query` | Run bounded read-only SQL against staged drought tables. | canvas_id, sql, limit, offset |
| `drought_dataframe_describe` | Inspect tables, columns, units and source metadata in a specified canvas. | canvas_id, optional table_name |
| `drought_dataframe_drop` | Remove one disposable staged table. | canvas_id, table_name |

Seven tools are callable by default; drop is implemented and manifest-visible through `disabledTool()` unless `DROUGHT_DATAFRAME_DROP_ENABLED=true`. DataCanvas tools remain registered when the provider is off and explain the operator configuration. No resources, prompts or Apps: every workflow is reachable through tools and no human interaction requires a separate UI.

Upstream readers have `readOnlyHint: true`, `idempotentHint: true`, `openWorldHint: true`. Reference and dataframe query/describe are read-only and closed-world. Staging producers keep the read-only annotation relative to the source but omit idempotence because repeated oversized reads create new disposable tables. Drop has `readOnlyHint: false`, `destructiveHint: true`, `idempotentHint: true`, `openWorldHint: false`. No auth scopes are needed for keyless use; canvas tenancy still uses the framework context.

## Overview and requirements

Serve agricultural, water-resource and climate analysis from the U.S. Drought Monitor (USDM): snapshots, historical series, county/state comparisons, and drought duration. Wrap only documented comprehensive statistics, DSCI and county-weeks families; do not expose threshold statistics, undocumented TimeSeries, program eligibility or arbitrary upstream URLs.

Support Bun and Node through STDIO and Streamable HTTP, with `sessionMode: 'stateless'`; no client round-trips. DuckDB native code excludes Workers. Upstream is free and keyless with no published rate limit. All source operations are GETs. Staged data is an in-memory analytical copy, never a write to an upstream system or a user store. Canvases disappear at restart/expiry.

User goals: resolve a place; inspect its latest/historical conditions; analyze a multi-year series; compare places or changes; find drought durations; retrieve every staged row or aggregate it with SQL.

## Shared contracts

### Geography

Use a strict discriminated `Geography` object with `areaType`, `aoi`, and required `hucLevel` only for the `huc` arm. `areaType` is `us | state | county | huc | tribal | climate_division`. Every string is bounded to 200 characters. Return a resolved `Area` with `areaType`, `id` (string, preserving leading zeroes), `name`, optional `state`, optional `hucLevel`. Never key data by display name alone.

| Area | Accepted input and normalization | Upstream selector |
|:--|:--|:--|
| US | Case-insensitive `us`, `conus`, `total`; `US` means both CONUS and Total | Lowercase selector; `us` expands to two output areas |
| State | Postal code, two-digit FIPS, exact full name; trim and case-fold | Two-digit FIPS; batch comma-joins FIPS |
| County | Five-digit FIPS or exact county name with comma plus state postal/full name; no guessed state | FIPS for one county; state postal batch followed by exact requested-FIPS filtering for multiple counties |
| HUC | Digit string of exactly hucLevel characters; hucLevel is 2, 4, 6 or 8 | Exact id plus hucLevel |
| Tribal | Bundled GEOID, case-normalized; do not infer names or remove suffixes | Exact GEOID; request one per call |
| Climate division | Four-digit bundled id, preserving leading zeroes | Exact id; request one per call |

Snapshot accepts one Geography, including the two-row US selector. Timeseries accepts `areas: Geography[]`, 1–100 entries, all the same areaType and (for HUC) level; deduplicate by canonical id. Single-item array repair is framework-owned. Do not split commas inside county names. HUC parent-to-child expansion is intentionally absent: name explicit child IDs from the reference tool. State-name and county-name matching normalizes case, punctuation and diacritics, but never fuzzy-matches or substitutes boundaries. Ambiguous names produce an actionable input error. Numeric strings retain their widths; do not guess lost FIPS/HUC zeroes.

### Dates, publication and empty outcomes

Accept real calendar dates `YYYY-MM-DD`; reject impossible dates and reversed requested ranges. Optional date strings allow `''` as unset. Do UTC date arithmetic; convert upstream query values to `M/D/YYYY`. A map week is Tuesday through Monday: snap both requested endpoints backward to the containing Tuesday, then use inclusive map-date bounds. Preserve requested dates and effective map bounds in the result. Normalize mapDate/validStart/validEnd to date-only strings; the latter describes the full Tuesday–Monday validity interval, not a clipped requested period.

Resolve `latestMapDate` once per workflow using `USStatistics/GetDSCI?aoi=conus` over UTC today minus 14 days through today; take the maximum actual returned date. Cache for five minutes with single-flight refresh. Never infer latest from the calendar or publish a Tuesday not yet returned. An empty latest lookup is `publication_unavailable`, not an invented current week. Thursday publication can leave the prior week as latest on Tuesday/Wednesday. A date later in the latest map's validity week resolves successfully; a later unpublished week does not.

Coverage begins `2000-01-04`. Snapshot before coverage/after the latest published week returns `{found:false, snapshots:[], guidance}` with the available span and `drought_list_reference(topic='coverage')` guidance. A shape-valid identifier absent from the bundle also returns found false when its direct lookup has no rows, with the matching reference topic. Unresolved names, ambiguous names and malformed identifiers are input errors. A known geography with no snapshot that week returns found false, explicitly describing missing data rather than absence of drought.

Timeseries and weeks intersect snapped bounds with published coverage. No overlap is success with empty rows and an enrichment notice naming coverage and the same tool with a revised range. A known area with no returned records is an empty result, never an unknown-ID inference. Return missing requested areas and missing expected `(id,mapDate)` observations explicitly; do not synthesize zeroes. Comparisons on unpublished weeks return an empty result and notice; differences never silently use an earlier week. Unknown names fail resolution before network work; shape-valid numeric IDs absent from a potentially stale bundle take the direct resolution path described below. Upstream missing observations remain disclosed partial data.

### Rows, units and provenance

`Buckets` is `{none, d0_d4, d1_d4, d2_d4, d3_d4, d4}` for cumulative statistics or `{none, d0_only, d1_only, d2_only, d3_only, d4_only}` for categorical statistics. Never expose ambiguous `d0`–`d3` output columns. Percent rows use percent units; area uses square miles; population count uses people. Preserve upstream numeric precision and nulls; do not normalize buckets to 100 or round them to make an invariant hold.

`WeeklyRow` includes `row_id` (stable 1-based index after sorting by area id then mapDate), Area fields, mapDate, validStart, validEnd, metric, statisticsType, unit, the applicable named buckets, `dsci: integer 0..500 | null`, and `dsciStatus: available | missing`. DSCI is always upstream `GetDSCI`, independent of metric; its experimental index status is explicit. Do not compute a replacement index from rounded percentages. Cumulative DSCI's sum and the categorical weighted-sum formula belong in reference data, not substitute outputs.

Join on canonical area id plus mapDate. County DSCI has FIPS, HUC DSCI has `hucid`; normalize these keys. US results map source names CONUS/Total to their canonical ids. State DSCI is name-only: resolve exact returned names against the state bundle and reject unmatched labels. Tribal and climate-division calls are single-selector requests: stamp the requested canonical id on each result, then join by mapDate. Their labels differ from the AOI table; climate DSCI's `climateDivision` is only a within-state number, not the four-digit AOI code. Reject duplicate keys and out-of-scope dates/IDs as `upstream_shape_invalid`; never overwrite duplicates silently. Missing DSCI joins stay null with a notice and missing-key count.

Every data/reference result carries `provenance: {sourceUrls: string[], retrievedAt, credit, dsciCitation, dsciExperimental:true}`. Include the public API/source URLs actually used, without adding secret-bearing/configured URLs. Credit is the Permission page's full wording: “The U.S. Drought Monitor is jointly produced by the National Drought Mitigation Center at the University of Nebraska-Lincoln, the United States Department of Agriculture, the National Oceanic and Atmospheric Administration and the National Aeronautics and Space Administration. Map courtesy of NDMC.” Citation: “Akyuz, F. A. 2017. Drought Severity and Coverage Index. United States Drought Monitor.” Staged table metadata retains provenance for describe and query results.

### Output fidelity and limits

Each tool output root is `z.object`, including optional arms; only inputs use discriminated unions. All fields have descriptions. Enrichment declares optional `notice`, `echo`, `total`, `truncated` fields with renderers; write required fields on every path or keep them optional. Defaults, clamped dates, counts, partial data and preview limits reach both surfaces.

Use readable field/value sections and complete tables, with units in headers and every returned row rendered. Dynamic labels, source names and SQL result strings are untrusted data: use dynamically sized code fences or escaped code spans that round-trip exactly, including CR/LF, pipes and backticks. Preserve strings verbatim in both representations; never flatten, strip HTML, defang links or truncate a cell. Render actual URL fields as links with the same URL; no link exists on only one surface. Tests parse the rendered representation and compare every value, including nulls and nested metadata. JSON fences are acceptable for irregular SQL cells, but a raw JSON dump is not the whole ordinary domain response.

Inline domain rows have a 40,000-character JSON-row budget, not an arbitrary fixed row count. Stage the complete normalized table when it exceeds that budget; return a fitting preview, full row count and exact table handle. Never present the preview as all data. Empty results mint a table only when time-series metadata requires continuation. A table contains at most 250,000 rows; rows plus complete retained metadata count against the tenant's 64 MiB quota. Exceeding the row or retained-byte bound rejects the entire request as `dataset_too_large` with instructions to split the range/area set. Enforce upstream bounds while reading, before uncontrolled materialization; no silent drain cap. Fetch input ranges remain bounded to coverage and 100 explicit areas. County/state nationwide comparison is separately allowed as a one-week bounded bulk workflow.

Bound the envelope as well as its rows: non-row fields, including missing observations, excluded areas, summaries, source URLs and table metadata, together have a 40,000-character serialized JSON budget; both the complete structured output and rendered content have an 80,000-character budget each. Preview/page rows shrink to fit the remaining budget, and a single record that cannot fit fails rather than truncating a value. Reference and weeks pages may return fewer than limit with a continuation cursor. Deduplicate provenance URLs. Time-series metadata stays complete inline whenever it fits. On overflow, automatically retain the complete metadata with the staged table and return nonempty prefixes of nonempty `areas`, `summary`, `missingAreas` and `missingObservations`, plus per-field `metadata_pages` totals, returned counts and next offsets. Automatic overflow preserves fitting responses and avoids an input mode that callers would have to discover only after failure. Complete retained metadata is tenant-scoped, charged to the byte quota and removed with the table. Fixed metadata or a single item that cannot fit remains `dataset_too_large`, naming its component. Missing observations and peak ties use lossless weekly date runs `{startMapDate,endMapDate,stepDays:7}`, grouped by area and missing component; gaps never merge. Describe without table_name returns bounded table/schema summaries; a named table preserves fitting metadata or automatically returns first pages. Query returns bounded source-table identity/provenance rather than duplicating every table's metadata.

The 100-area and full-coverage date bounds are individual input ceilings, subject to request-plan, upstream-byte, normalized-data and response-metadata budgets; do not advertise their Cartesian product as guaranteed. Preflight the resolved request plan before fetching: at most 64 logical upstream requests, including latest discovery and unknown-ID resolution, and at most 64 MiB upstream response bytes in aggregate, including discarded bulk-selector rows and retry bodies. Exceeding the plan cap returns dataset_too_large with plannedRequests, maxRequests and an executable smaller request using the same tool, fewer explicit areas or a shorter range. A bound reached while reading aborts outstanding work and rejects atomically. The workflow deadline remains a timeout rather than partial success. This permits full-history compact state/HUC/tribal series and nationwide one-week comparisons without requiring thousands of year-by-area requests.

## Tools — detail

### drought_list_reference

| Input | Type/default | Meaning |
|:--|:--|:--|
| topic | `categories | dsci | area_types | coverage | states | counties | tribal | climate_divisions | huc` | Required reference family |
| nameContains | Optional string, ≤200 chars | Local all-token normalized match across the complete family, before pagination |
| state | Optional postal/FIPS/name | Restrict county records; normalize through state bundle |
| hucLevel | Optional 2/4/6/8 | Required for topic huc |
| cursor | Optional opaque string, ≤2,048 chars | Binds topic and normalized filters to an offset; mismatch is invalid_cursor |
| limit | Integer 1–200, default 50 | Reference page size |

Output: `{topic, records, totalCount, nextCursor:null|string, hasMore, bundleVersion, sourceMetadata, provenance}`. Records use a declared per-topic nested union. Categories include None and D0–D4 labels, official example percentile and SPI/SPEI ranges, and S/L/SL impact flags with meanings. Area types include identifier formats and metric support. Coverage includes the start and weekly publication rule; this offline reference does not claim a live latest date. DSCI includes both formulas, 0–500 scale and experimental caveat. Geography records include exact ids, names, state where known, hucLevel where applicable, and `sourceVintage`/`currentUsdm` for counties. `state` on another topic or hucLevel on non-huc is `invalid_reference_filter`; reject ignored filters.

Zero hits: “No reference names match these filters; call drought_list_reference with the same topic and without nameContains to browse.” Reference data is paginated, never staged.

### drought_get_current_severity

Inputs: `area: Geography`, optional `date`. Output: `{found, requestedArea, resolvedAreas, requestedDate:null|string, effectiveMapDate:null|string, latestMapDate, availableFrom, snapshots, guidance:null|string, provenance}`. Each snapshot includes Area/mapDate/validity, `areaPercentCumulative`, `areaPercentCategorical`, `areaSqMilesCumulative`, `populationCountCumulative:null|Buckets`, `populationStatus: available | unsupported | missing`, dsci and status, and `dsciChange4Weeks`/`dsciChange52Weeks` each `{baselineMapDate, baselineDsci:null|integer, delta:null|integer, status:available|before_coverage|missing}`. A delta is current minus exactly 28/364 days earlier, never nearest-row, never percent change. Do not fabricate a baseline before 2000.

Population exists only for us/state/county in this surface. For HUC/tribal/climate division return null plus unsupported and make no population request. A missing supported result is distinct from unsupported. Current severity obtains cumulative and categorical area percent, cumulative area square miles, supported cumulative population count, and one DSCI range from the 52-week baseline through the target date; run independent requests with shared concurrency bounds. A required severity component missing produces no snapshot for that area and a notice naming the absent component; partial population/DSCI remains explicitly nullable. No snapshot stitches different map dates together.

### drought_get_timeseries

| Input | Type/default | Mapping |
|:--|:--|:--|
| areas | Geography array 1–100 | Homogeneous type/level; one or more canonical ids |
| startDate, endDate | Required ISO dates | Inclusive containing map weeks |
| metric | `area_percent` default; `area_sq_miles | population_percent | population_count` | Comprehensive endpoint suffix |
| statisticsType | `cumulative` default or `categorical` | statisticsType 1 or 2 |
| canvas_id | Optional CanvasIdSchema or blank | Reuse a known canvas when staging; omit to mint if needed |

Output: `{areas, requestedRange, effectiveRange:null|{startDate,endDate}, latestMapDate, metric, statisticsType, unit, rows, rowCount, missingAreas, missingObservations, summary, staging:null|StageHandle, provenance}`. `rows` is the complete inline set or exact preview. `summary` covers all returned data, grouped per area: observationCount, first/last mapDate, peakDsci `{value,mapDateRuns}` or null, peakD3D4 `{value,mapDateRuns,unit}`. For categorical rows D3+D4 is their sum; for cumulative use d3_d4 alone. Preserve all tied peak dates through the shared lossless weekly runs. Summary fields do not imply absent weeks are zero.

Fetch metric and DSCI in parallel per batch. State FIPS batch; county batches use their state postal selectors and filter to requested FIPS; a single county uses its exact FIPS selector. US handles conus/total; HUC/tribal/climate use single selectors. Fetch compact selectors across the full requested range; do not multiply every selector by calendar years. Partition county bulk selectors into bounded date windows when the bundled county count and inclusive weeks make a full-range response too large; estimate at 1,024 raw JSON bytes per county-week, target at most 8 MiB per planned response, and retain the hard 16 MiB streamed response cap if reality exceeds that estimate. De-duplicate snapped window boundaries. Apply the shared request-plan cap, concurrency 3 and total deadline. A state batch may contain 52 ids; county batches may contain all configured supported states for a single-week comparison, but timeseries filters only explicit requested counties. Population for any unsupported area type is `unsupported_metric` before I/O. Partial missing observations never count as successful zero drought.

Zero data: “No USDM observations are available for the resolved areas and published weeks; call drought_get_timeseries with a different range or drought_list_reference(topic='coverage').”

### drought_compare_areas

Strict input arms: `{scope:'states', ...}`; `{scope:'counties', state?:string, ...}`. Shared fields: optional date (latest default), optional baselineDate, `metric: dsci | d2_d4 | d3_d4` default dsci, `direction: desc|asc` default desc, `limit` integer 1–200 default 20, optional canvas_id. State omitted under county scope means nationwide; no state argument under states scope. Dates use common publication rules and baseline must not follow target.

Fetch all supported state FIPS or county postal codes in batches on exactly one target map; use GetDSCI for dsci or cumulative area percent otherwise. Repeat for baseline only when supplied. Return `{scope, state:null|string, metric, unit:'index'|'percent', changeUnit:'index'|'percentage_points', targetMapDate, baselineMapDate:null|string, rows, comparedCount, excludedAreas, staging:null|StageHandle, provenance}`. Rows have row_id, canonical id, name, state where applicable, targetValue, baselineValue:null|number, change:null|number, rankedValue, rank. Rank targetValue without baseline, target minus baseline otherwise. Sort requested direction, tie-break id ascending; rank uses competition ranking (1,1,3). Record counties/states with missing sides in excludedAreas and never replace missing baseline with zero. This is actual severity ordering, never a synthetic score.

The inline top limit is a preview. If there are more comparable rows than limit, stage the complete ranked table even when its byte size fits; otherwise a non-top result would be unreachable. If provider is off, fail before making a partial ranking look complete. Nationwide means USDM-supported 50 states, DC and PR, not an invented all-territories guarantee; expose the resolved included states. Nationwide state/county selectors come from the bundle's actual supported set. Empty comparison: “No comparable published observations exist for these dates; call drought_compare_areas with dates inside the coverage shown by drought_list_reference(topic='coverage').”

### drought_get_weeks_in_drought

Inputs: required startDate/endDate, `minCategory: D0|D1|D2|D3|D4`, `minWeeks` integer ≥1 and ≤number of requested inclusive map weeks, `mode: consecutive|non_consecutive` default consecutive; optional `states` array 1–54 or `county` county-name/FIPS string, mutually exclusive; optional cursor, `limit` 1–200 default 50. Normalize category case; map Dn to dx n. Omitted states means all supported states. A county resolves first, fetches its state's weeks endpoint, then filters exact FIPS. Echo all resolved filters. Do not silently drop a state or widen an unknown county to statewide.

Output: `{mode, minCategory, minWeeks, thresholdRule:'any_area_at_or_above', states, county:null|Area, requestedRange, effectiveRange, latestMapDate, rows, totalCount, nextCursor, hasMore, provenance}`. Consecutive rows retain upstream FIPS/county/state, startDate/endDate and consecutiveWeeks within the effective window, adding `startMayExtendEarlier` when startDate equals effective start and `endMayContinue` when endDate equals effective end plus six days. These flags express uncertainty, never proof of continuation; interior boundaries are false. Non-consecutive rows omit both flags. One county can have multiple streaks. Preserve the upstream Monday end after the final Tuesday. Counts are authoritative; minWeeks above clipped coverage is an empty success. Fetch each deduplicated supported state separately under one budget, preflighting all states plus publication discovery; comma-separated duration selectors return empty upstream. Abort and settle siblings on failure, merge complete state responses, then county-filter, sort and page. Never split time windows and sever streaks. Cache only complete immutable results five minutes (LRU, 32 entries, 64 MiB total). Cursor expiry asks the caller to restart.

Zero hits: “No counties meet this threshold; call drought_get_weeks_in_drought with a lower minWeeks or minCategory, or a wider date range.” This tool reports duration statistics only; normal grazing periods and other program criteria are outside scope.

### Dataframe tools

`StageHandle` is `{canvas_id, table_name, row_count, columns:[{name,type,unit:null|string}], expires_at, describe_tool:'drought_dataframe_describe', query_tool:'drought_dataframe_query'}`. Always return both tool names with the token. Tables are uniquely server-named `drought_<random>`; use the installed CANVAS_IDENTIFIER_REGEX (63-character maximum) for identifiers. Explicit ColumnSchema uses VARCHAR for codes, DATE for dates, INTEGER for row_id/DSCI, DOUBLE for fractional metrics, and nullable columns where data is missing. Never infer numeric types from initial all-zero rows.

`drought_dataframe_describe` requires canvas_id; optional table_name. Use `acquire(id,ctx)` then `describe({tableName})`. Output `{canvas_id, expires_at, tables:[{name,kind,rowCount,columns,expiresAt,metadata}]}`. Metadata contains source query, resolved areas/range, metric, statisticsType, units, join/missing-data details and provenance. With a named table, `metadata_field` (`areas`, `summary`, `missingAreas`, `missingObservations`), `metadata_offset` (nonnegative, default 0) and `metadata_limit` (1–100, default 20) return additive `metadata_page:{field,items,total,offset,next_offset}` from the retained snapshot without upstream reads. Past-end offsets return empty items and null continuation. Missing table or collection uses `missing_table` or `invalid_metadata_page`. An empty specified canvas is a successful empty list. Never enumerate other tokens.

`drought_dataframe_query` requires canvas_id and sql (1–16,384 chars), `limit` integer 1–500 default 100, `offset` integer 0–250,000 default 0. Only one SELECT/CTE/FROM-first read expression without a terminal semicolon. No registerAs, export, path, URL, extension or arbitrary file API is exposed. Pass `SELECT * FROM (<sql>) AS drought_result LIMIT <limit+1> OFFSET <offset>` directly to `instance.query` with rowLimit limit+1, denySystemCatalogs true, and a combined caller/5-second timeout signal. Integers in the wrapper are schema-validated. The provider validates the complete wrapped expression through its statement-count, type, parse-tree, function and plan gates before execution; no separate unbounded validation query or direct DuckDB connection is needed. Smuggled parentheses/statements must fail those gates, verified with real DuckDB adversarial tests. Do not call assertReadOnlyQuery with a SQL string: its installed signature requires engine metadata, which the provider owns.

Return `{canvas_id, columns, rows, returnedCount, offset, next_offset:null|integer, has_more, countIsExact:boolean, tableMetadata}`. Size the returned prefix to 40,000 serialized row characters; include one sentinel to determine has_more and next_offset is offset+returnedCount. `countIsExact` means this query page is exhaustive at offset zero, not a claimed full count from truncated QueryResult.rowCount. A single projected row above budget raises query_row_too_large rather than cutting a string. For a complete staged-table read, describe then `SELECT * FROM <table> ORDER BY row_id`, progressing next_offset until null. Every row has stable row_id; arbitrary SQL pagination requires caller ORDER BY on stable keys. Exact counts use `SELECT COUNT(*)`; no total is fabricated from the engine cap. Empty query is successful rows=[]; notice routes to drought_dataframe_describe with the same token. Queries cannot mint a canvas or materialize extra tables.

`drought_dataframe_drop` requires canvas_id and table_name. Return `{canvas_id, table_name, dropped:boolean}`; false means table was already absent. Drop only one table, not clear or tenant-wide deletion. Catch acquire's canvas_not_found at this explicitly required adapter boundary and raise the tool's own contract, whose recovery does not suggest recreating data just to delete it. No automatic confirmation round: opt-in registration and the explicit token/table are sufficient for disposable copies.

## Error contracts

Declare applicable entries inline on each tool; do not share a runtime errors array. Services throw matching `data.reason` with `thrownBy:'service'` in the tool definition. Baseline network/timeout/cancellation errors may bubble; no raw upstream body, HTML, stack, filesystem path or SQL engine cause is sent to the client.

| Tool(s) | Reason / code | When | Verbatim recovery |
|:--|:--|:--|:--|
| All geography readers; reference | ambiguous_area / ValidationError | Multiple exact normalized name matches | Call drought_list_reference for the geography type and supply its exact identifier. |
| Timeseries, compare, weeks | unknown_area / NotFound | Name cannot resolve; an empty numeric-ID lookup alone does not establish invalid geography | Call drought_list_reference for the geography type to find a supported identifier. |
| All geography readers | invalid_area / ValidationError | Identifier shape/combination invalid | Call drought_list_reference with topic area_types and supply the documented geography format. |
| Timeseries | unsupported_metric / ValidationError | Population requested for unsupported type | Call drought_list_reference with topic area_types, then use an available metric in drought_get_timeseries. |
| Dated readers | invalid_date_range / ValidationError | Impossible/reversed dates or invalid baseline order | Call drought_list_reference with topic coverage, then retry this tool with ordered calendar dates. |
| Dated readers | publication_unavailable / ServiceUnavailable, retryable | Latest discovery yields no usable maps | Retry drought_get_current_severity later; call drought_list_reference with topic coverage for the publication schedule. |
| Timeseries, compare, weeks | dataset_too_large / ValidationError | Row/byte budget would be exceeded | Narrow dates or areas in drought_get_timeseries, drought_compare_areas, or drought_get_weeks_in_drought and retry. |
| All upstream readers | upstream_shape_invalid / ServiceUnavailable | Malformed JSON, duplicate keys or incompatible shape | Retry the same drought tool later; call drought_list_reference with topic coverage to check supported data. |
| Reference, weeks | invalid_cursor / ValidationError | Invalid cursor or changed filter | Restart drought_list_reference or drought_get_weeks_in_drought without cursor and retain the same filters. |
| Reference | invalid_reference_filter / ValidationError | Filters do not apply to topic | Call drought_list_reference with topic area_types and use filters belonging to the selected topic. |
| Staging producers; dataframe trio | canvas_unavailable / ConfigurationError | Canvas provider off or native engine unavailable | Use the npm or Docker analytical installation with @duckdb/node-api and CANVAS_PROVIDER_TYPE=duckdb; MCPB supports inline results only. |
| Staging producers | staging_capacity_exhausted / RateLimited, retryable | Retained table or byte capacity unavailable | Reuse a returned canvas_id with a free slot, or retry after the earliest relevant expiry when known. |
| Producers and query | staging_busy / RateLimited, retryable | Active acquisition or query slots occupied | Retry after active workflows or queries finish. |
| Staging producers; query/describe | canvas_not_found / NotFound | Unknown/expired/other-tenant token | Re-run drought_get_timeseries or drought_compare_areas to stage data and use the returned canvas_id. |
| Staging producers | canvas_capacity_exhausted / RateLimited, retryable | Framework mint cap reached | Reuse a canvas_id already returned by drought_get_timeseries or drought_compare_areas, or retry after expiry. |
| Query/describe | missing_table / NotFound | Named table absent | Call drought_dataframe_describe with the same canvas_id, or re-stage with drought_get_timeseries or drought_compare_areas. |
| Query | invalid_sql / ValidationError | SQL binding/parser failure | Call drought_dataframe_describe with the same canvas_id and retry drought_dataframe_query using its columns. |
| Query | sql_execution_error / ValidationError | Cast/range/data execution error | Inspect columns with drought_dataframe_describe, then retry drought_dataframe_query with TRY_CAST or a narrower filter. |
| Query | sql_read_only / ValidationError | Gate rejects write, external read or system access | Call drought_dataframe_describe and query only its staged tables with drought_dataframe_query. |
| Query | query_row_too_large / ValidationError | First projected row alone exceeds output budget | Inspect columns with drought_dataframe_describe and project smaller values in drought_dataframe_query. |
| Query | dataset_too_large / ValidationError | Combined source metadata exceeds the non-row budget | Re-stage the needed dataset in a new canvas with drought_get_timeseries or drought_compare_areas, omitting canvas_id, then query the returned token. |
| Drop | canvas_not_found / NotFound | Token absent; nothing to remove | Nothing remains to remove; use drought_dataframe_describe only with another canvas_id already returned to you. |

Adapt every framework SQL gate reason (`SQL_GATE_REASONS`, including system_catalog_access) to sql_read_only while preserving the rejection category in safe structured context. Preserve invalid_sql/sql_execution_error separately. Engine faults remain DatabaseError; do not label engine memory/I/O failures as caller SQL errors.
