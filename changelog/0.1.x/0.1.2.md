# 0.1.2 — 2026-10-20

## Changed

- **Node acquisition** uses a reusable, server-owned HTTP/1.1 dispatcher with graceful teardown; Bun retains native fetch ([#7](https://github.com/cyanheads/us-drought-monitor-mcp-server/issues/7)).
- **Documentation and install metadata** describe analytical retention, portable bundle limits and current workflow contracts.

## Fixed

- **Duration acquisition** fetches each deduplicated state separately and merges complete results before filtering and pagination ([#4](https://github.com/cyanheads/us-drought-monitor-mcp-server/issues/4)).
- **National selection** uses the upstream `us` selector for CONUS plus Total; rejected upstream requests include typed recovery guidance ([#5](https://github.com/cyanheads/us-drought-monitor-mcp-server/issues/5)).
- **Consecutive duration rows** disclose uncertainty at the effective map-week boundaries with `startMayExtendEarlier` and `endMayContinue` ([#6](https://github.com/cyanheads/us-drought-monitor-mcp-server/issues/6)).
- **Staging capacity** reuses the tenant's most recently used service-owned canvas with free table slots and distinguishes transient `staging_busy` errors from retained-capacity exhaustion ([#8](https://github.com/cyanheads/us-drought-monitor-mcp-server/issues/8)).
- **Time-series metadata overflow** automatically retains complete rows and metadata, including zero-observation results, with bounded continuation through `drought_dataframe_describe` ([#9](https://github.com/cyanheads/us-drought-monitor-mcp-server/issues/9)).
- **Legacy Connecticut selectors** retain empty-success lookups with planning-region guidance; comparisons omit exactly the eight legacy county identifiers ([#10](https://github.com/cyanheads/us-drought-monitor-mcp-server/issues/10)).

## Dependencies

- **undici** absent → `8.12.2` (production dependency for the Node dispatcher).
